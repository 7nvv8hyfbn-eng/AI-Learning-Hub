# 项目内容与发布

**首次部署和每次增量更新，都必须同步社区帖子及侧栏、通识基础、教程中心、模拟实训这四类项目内容。** 从 GitHub 拉取代码、构建前端或重启服务，不等于已经将内容导入目标数据库；不能只更新其中一类。此规则适用于校园服务器、飞牛及其他部署环境。

## 正式内容来源

导入来源是仓库内已提交的 `server/resources/project-content/content.json`，校验清单为同目录的 `manifest.json`，无需另找本地数据库或从其他服务器复制账号和业务库。

| 板块 | 当前随项目导入和更新的内容 | 仓库中的配套素材 |
| --- | --- | --- |
| 社区 | 100 篇原创帖子、200 条配套回复及配图、4 个关联话题、3 个官方展示主页 | `server/resources/community-starter/images/` |
| 通识基础 | 24 门课程、144 节课时、完整正文与练习、72 张课程图片 | `packages/catalog-assets/` |
| 教程中心 | 24 条内容，含图文、视频、附件、封面、分类及项目公共播放列表 | `frontend/public/demo/resource-hub/` |
| 模拟实训 | 13 项已发布实训、90 个确认式模拟步骤、发布快照、13 张封面 | `packages/catalog-assets/` |

素材的具体文件、大小及摘要以内容包的 `media` 字段为准，必须随同一 Git 提交的清单一起打包。教程中心现有 16 个视频保留“8秒演示片段”标识。素材目录名称中的 `demo` 和 `community-starter` 是保留的技术路径，不表示应执行演示 Seed 或旧账号导入脚本。

## 内容边界

内容统一署名“平台内容”，不链接个人主页。清单通过明确字段提取，只包含内容、分类、课程结构与媒体；不包含账号资料、凭据、权限、个人记录或模拟互动数。必要数据库关联使用目标环境现有管理员，不改动其账号。新环境管理员由该环境私有配置通过 `bootstrap` 初始化。正式镜像不携带测试账号夹具，不运行 Seed。

社区侧栏另外初始化经授权的“AI 学习助手、实训指导、课程运营”三个官方展示主页。清单仅包含展示文案；内部标识由同步器生成，保留邮箱使用不可投递的 `example.invalid` 域名，密码为空，不绑定外部登录方式、MFA 或管理权限。只关联现有的零权限 `community_official` 身份角色；如果该角色已有管理权限则拒绝同步。同名账号保留，不接管、不赋权。主页介绍明确说明展示用途，不承诺在线问答服务。话题交流数从真实帖子关联计算，不生成关注、粉丝、实训参与人数或完成率。

服务器上的普通用户发帖、评论和上传文件属于该环境业务数据，不会自动进入项目内容包。只有经审查纳入正式清单的项目帖子、课程和教程，才随后续部署同步；不得为更新项目内容导出或覆盖用户信息。

## 开发期维护内容包

开发期更新内容后，在 `server/scripts/build-project-content.ts` 递增发布版本及对应内容版本，然后在 `server` 执行：

```sh
npm run content:prepare
npm run content:check-source
npm run build
npm run content:check
```

生成器仅用于开发；正式同步仅读取经过审查、提交的清单。清单文件和媒体须一起提交。修改同一版本的摘要或以旧版本覆盖新版本会失败。

## 预览和同步

首次部署先完成迁移和 `bootstrap`，使用该环境私有配置初始化管理员，再同步四类内容及社区侧栏；增量更新使用原业务库和存储，备份后完成迁移、`bootstrap` 与内容同步。正式发布统一使用下文的发布入口，不另行导入演示用户。

以下命令在已构建的 `server` 运行目录或对应服务镜像中执行，使用目标环境自身的 `DATABASE_URL`、存储及安全配置；使用开发机数据库配置执行，只会同步开发库，不会更新校园业务库。`content:preview` 可用于发布前排查，写入前必须完成备份：

```sh
npm run content:preview
npm run content:sync
npm run content:verify
```

预览不写入。同步先校验全部素材，然后在数据库事务内串行执行；同版本重跑不重复新增内容或上传文件。每条内容通过稳定标识、期望摘要、上次导入摘要及版本记录在 `system_settings` 的 `project_content:item:*` 中。

缺失条目新增，未被人工修改的托管条目升级。人工编辑、下架、删除和无法确认归属的旧条目保留并记录为 `protected`。同名或同 ID 不能单独证明归属。移出清单不会删除线上内容。课程和实训升级创建新版本，保留历史章节、实训快照与学习记录；帖子升级保留修订、真实评论及互动。除上述三个展示身份的初始化和未被人工编辑的展示文案外，账号与个人记录不在同步写入范围。

同步失败时事务不会写入完成记录；已上传文件按内容摘要复用，重试不生成演示凭据。同步报告包含 Git 提交、四类版本、增量数量、人工冲突及媒体校验结果。冲突条目明确记录为保留现场状态，不计为导入成功。

## 正式发布

所有服务器的首次部署与增量更新使用同一入口，不依赖某台服务器的数据库备份，不再配置 `COMMUNITY_STARTER_PACK`。保持 `LOAD_DEMO_DATA=false`，学生端构建使用 `VITE_DATA_MODE=api`。

先按 [应用版本流程](../README.md#版本与发布) 发布 main 和对应标签，再构建并保存固定提交对应的镜像。应用版本由根目录 `version.md` 维护，独立于本内容包版本；镜像构建须传入相同 `APP_COMMIT_SHA`，各端生成 `dist/version.json`。将 `ENV_FILE` 指向该环境私有配置，`APP_COMMIT_SHA` 指向已推送的完整提交，`APP_IMAGE_TAG` 指向对应镜像标签，然后执行：

```sh
bash deploy/compose/release.sh
```

发布入口先核对三端镜像的应用版本及提交，写入 `release-version.json`，任何不一致都在停写之前拒绝。之后顺序固定为停写与备份、迁移、基础初始化、四类内容及社区侧栏同步、校验、开放服务。Compose 的 `content-sync` 是 API 依赖；API 启动也核验当前镜像的完成记录，绕过 Compose 不能跳过内容同步。使用环境自有的外部持久卷时，通过受控 Compose 配置指向已有卷，不创建替代业务库。

备份目录包含数据库、上传文件、镜像列表、私有环境配置及内容报告，权限为仅部署操作者可读。保留旧镜像、分包和备份；不要运行 `down -v`、Seed 或导入测试账号脚本。回退代码不自动降级内容，须明确核对旧代码兼容性；需要恢复数据时使用对应备份并审查新增业务数据，禁止自动恢复覆盖。

## 导入验收与遗漏排查

发布记录必须覆盖四类内容及社区侧栏，保存 `content-sync.log`、`content-verify.log` 中的内容包版本、摘要、Git 提交、媒体校验及条目结果，并分别汇总社区、课程、教程、实训、话题和官方展示主页的新增、更新、未变和保护数量。回复、分类及播放列表也需核对，不能用包含用户自建内容的数据库总条数代替项目内容验收。

- 社区：检查项目帖子正文、配图、200 条配套回复及“平台内容”署名，确认原有用户帖子、评论与真实互动保留。
- 通识基础：检查 24 门课程的发布版本、144 节课时及插图。新版可能沿用旧课程标题，需比较正文、课时与封面；主题分类数量不能代替课程内容版本，也不能通过删除主题来重建课程。
- 教程中心：检查 24 条内容、分类和公共播放列表；访客检查公开封面，登录后实际检查图文正文、视频播放及附件下载，确认演示视频标识保留。
- 模拟实训：检查 13 项已发布实训、90 个步骤、13 张封面，实际完成模拟步骤和提交；总分为 100，不声称执行了真实命令或连接了真实硬件。
- 社区侧栏：检查 4 个话题能打开实际关联帖子，3 个官方展示主页可见且没有登录凭据、外部身份或管理权限；现有账号、关注和互动保持不变。

`protected` 表示保留了人工修改、下架、删除或无法确认归属的旧记录，必须列出具体条目和原因。即使 `content:verify` 通过，也不能将这些条目报告为已替换成新版；需要处理时先核实现场内容，不清除保护记录或强制覆盖。

若从 GitHub 增量更新后页面仍是旧内容，依次核对：实际运行 API 的 `/api/v1/version` 与三端制品是否属于待发布提交；镜像是否包含该提交的清单和媒体；前端是否使用真实 API 且连接正确服务；同步命令是否连接实际业务库；同步报告是否有失败或 `protected` 条目。修正遗漏后重跑统一同步并校验，不能仅凭 Git 已更新、容器健康或页面标题相同判断发布完成。
