# 社区举报与申诉

举报复用 `CommunityReport`，处罚复用 `CommunityModerationAction`、操作限制、通知和审计。帖子、评论、资源作品、公开合集及账号资料以实体外键和修订号关联，不另存正文副本。资源作品仍引用原社区帖子。

## 处理流程

举报和申诉使用 `pending`（待处理）、`reviewing`（处理中）、`resolved`（已处理）、`rejected`（驳回）四个状态。管理员领取后提交决定；版本校验与数据库事务防止重复领取、重复处罚。处罚、举报结果、站内通知和审计共同提交，任一步失败则回滚。

后台社区运营中的治理工作台包含待复核、举报、申诉和处理中事项，支持领取、退回、分类与负责人筛选、处理记录。待办默认48小时到期，在工作台提示逾期；不额外发送邮件或建立工单系统。举报数量本身不会触发封号或自动限制。

| 动作 | 默认约束 |
| --- | --- |
| 提醒 | 关联具体内容修订，不影响正常操作 |
| 限制单项功能 | 必须指定功能和期限，复用操作资格检查 |
| 临时禁言 | 同时限制发帖和评论，必须有期限 |
| 内容下架 | 作用于对应内容，期限可选 |
| 账号封禁 | 额外要求用户写入与会话撤销权限；永久封禁仅超级管理员可执行 |

期限最长一年。处理理由和具体规则依据必填，不能处理自己的内容；处理管理员账号须超级管理员权限。到期、撤销和申诉通过仅解除对应处罚，仍检查当前内容审核、作者删除、合集私密状态及其他有效处罚。

## 用户申诉与隐私

消息通知和本人主页可进入 `/community/governance`，查看涉及内容、修订、规则依据、理由、期限与处理记录。仅在对应版本仍可读取时展示原实体正文；新的私人草稿不会因旧举报而暴露。

申诉关联本人具体处罚或被拒绝的内容审核修订，每个目标同时只能有一项待办。同样请求返回已有记录；处理完成后允许提交新理由或新证据。每账号每天最多5次、每来源地址每天最多100次。举报证据最多3个 HTTPS 链接，不向被举报人返回举报人身份或举报证据。

不能正常登录的用户可访问 `/account-recovery`，用现有账号密码验证身份后获得10分钟、仅限本人处理记录与申诉的凭据；不建立普通登录会话。忘记密码继续使用原邮件找回流程，改密不会自动解除封禁。未配置可用邮件时，忘记密码的邮件恢复渠道不可用，需由有权限的管理员按现有账号流程核验。

## 权限与可见性

所有治理读取和写入由服务端鉴权，敏感操作留审计。普通审核员无法写入角色、读取身份材料、查看私人草稿或修改系统密钥；内容编辑没有治理权限。申诉须由非本人、非原处理人复核，账号封禁申诉仍执行对应用户管理权限校验。

有效处罚直接参与数据库查询，覆盖社区、门户推荐、搜索、作者页、教程中心、公开合集、图片与视频访问。已有媒体链接每次请求仍验证可见性。没有新增缓存、定时恢复任务或通用规则引擎。

## 接口与部署

前台版主使用独立的 `FrontendModeratorGrant` 范围授权，继续从学生端登录，不取得后台权限。后台“用户与账号”详情通过 `user.moderator.manage` 配置社区、教程中心及允许动作；授权变更必须携带用户修订号、幂等键和原因，并记录授予人、时间与审计。

社区帖子归 `community`，带 `ResourceContribution` 的作品归 `tutorials`，评论跟随父内容。服务端查询真实归属及当前授权，撤权后旧页面和重复请求立即被拒绝。前台只能下架内容、限期禁言或限期封禁，不能处理自己、受保护管理账号或私人草稿。禁言覆盖发帖、评论、教程发布和已发布内容修改；封禁撤销现有会话并向本人返回处理原因。原举报、收藏、屏蔽、申诉和后台 MFA、管理网规则保持。

- `/api/v1/community/governance`：本人记录、举报和申诉。
- `GET /api/v1/community/moderation/targets/:type/:id`：当前对象与允许动作。
- `POST /api/v1/community/moderation/targets/:type/:id/decision`：前台版主处置，必填 `expectedRevision`、`action`、`reason` 和 `Idempotency-Key`；禁言、封禁还须填写 `expiresAt`。
- `PUT /api/v1/admin/users/:id/moderator-grants`：后台配置或撤销前台授权。
- `/api/v1/community/recovery`：身份验证、本人记录和申诉。
- `/api/v1/admin/community/governance`：治理工作台、领取、决定和撤销。
- 原举报、操作限制入口复用同一治理事务；旧直接隐藏或封号接口须改用有依据的治理决定。

`20260907220000_community_governance` 是增量 Migration，新增申诉表、外键、修订、领取及处罚字段，保留既有举报、处罚、限制、账号和配置。历史停用账号和操作限制补入可申诉的关联记录，未记录的旧依据明确标注待核查。升级执行 `prisma migrate deploy` 和现有必要元数据 `bootstrap`，不执行 Demo Seed。

前端正式构建必须设置 `VITE_DATA_MODE=api`；网络或鉴权失败直接显示错误，不回退 Mock。显式 Mock 仅供开发演示。

前台版主增量迁移为 `20260909130000_frontend_moderators`；迁移后执行现有 `bootstrap` 注册专门权限，不重新导入演示数据。已有帖子、教程、文件及后台角色保持。

## 公开用户标签

用户详情的“公开标签”只控制展示，不修改身份、学校、会话、角色或版主授权。`GET/PUT /api/v1/admin/users/:id/badges` 要求 `user.read` 和 `user.badge.manage`；修改须携带公开资料的 `expectedRevision` 与操作原因，冲突返回 409，审计保留前后设置。

`CommunityProfile.customBadges` 保存最多 3 个普通文字标签，`hiddenAutomaticBadges` 保存自动身份标签的隐藏代码，复用资料 `revision`。迁移 `20260910140000_public_user_badges` 将两字段初始化为空；随后执行 `bootstrap` 注册管理员专用权限，不运行 Seed。

服务端通过可信身份、当前有效前台版主授权与显示覆盖统一计算 `badges`。两个范围只显示一个版主标签；隐藏设置跨刷新、登录和重启保留，撤销授权后不能恢复失效身份。官方、教师、导师和版主名称不能作为普通标签添加。展示标签不参与业务权限判断，`verifiedType` 保持原有语义。

作者、评论、引用、教程、个人主页和用户检索共用前台标签组件，默认显示两个，其余可通过提示读取。普通读取和已有窗口恢复机制更新作者副本，无新增轮询或 WebSocket。

## 验证

本地分别在 `server`、`admin-web` 执行 `npm run check`，在 `frontend` 执行 `VITE_DATA_MODE=api npm run check`。治理集成测试为 `server/test/governance.e2e.spec.ts`，只允许专属隔离 PostgreSQL `127.0.0.1:55439/community_governance`。内容检测回归使用另一个专属空库 `community_content_detection`。运行前先迁移空库，测试仅创建合成账号与数据；不得指向现行业务库。

前台版主真实回归使用 `test/frontend-moderators.e2e.spec.ts`，要求 `FRONT_MODERATOR_ISOLATED=true` 且 PostgreSQL 为 `127.0.0.1:55439/frontend_moderators` 的专属空库，覆盖授权撤销、跨范围处罚、事务回滚、处罚期限、共享文件和旧视频 Range 地址。
