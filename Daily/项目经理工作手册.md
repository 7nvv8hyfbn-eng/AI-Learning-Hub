# 项目经理工作手册（AI-Learning-Hub 实训）

> 适用角色：项目经理 · 对接：前端 / 后端 / 项目总监

## 一、项目经理要干什么

| 环节 | 具体动作 |
|------|---------|
| 接需求 | 拿到迭代目标后，拆成「前端做什么、后端做什么」，写清边界（例如：不改布局 / 导航 / 侧边栏） |
| 定分工 | 给每个人下发可执行任务，明确交付物和时间点 |
| 管进度 | 每天跟进：完成 %？卡在哪？谁依赖谁？ |
| 协调 | 前后端接口对接、资源冲突、阻塞问题，由你推动 |
| 控质量 | 阶段评审 + 验收，确认新功能没有破坏旧功能 |
| 闭环 | 缺陷记录 → 分配 → 修复 → 复核，全部关闭才算完成 |
| 上报 | 解决不了的卡点，带着方案上报项目总监 |

## 二、怎么干（工作方法）

### 1. 需求拆解公式
> 每个任务 = 做什么 + 约束（不改什么）+ 交付物 + 验收标准 + 截止时间

示例：
```
前端工程师（王云）
任务A：社区全部 Icon 替换
- 保持原有 DOM 位置 / 宽高尺寸不变
- 三种交互状态：默认 / hover / 选中
- 交付物：替换完图标的社区页面
- 自查：页面布局完全不受影响
```

### 2. 排期方法（倒推法）
```
上线日 ← 验收 + 缓冲（1天）← 开发完成 ← 接口联调窗口 ← 拆任务排期
前后端联调是关键卡点 → 提前约定接口契约（字段 / 错误码）
```

### 3. 每日站会（10 分钟）
- 昨天做了什么
- 今天做什么
- 有没有阻塞（有就当场协调，或上报）

### 4. 风险预判清单
- 后端出现技术卡点 → 提前评估是否裁剪需求
- 联调排期冲突 → 提前约定时间
- 单人任务量过大 → 拆分或协调资源

## 三、项目经理要会什么（核心能力）

| 能力 | 说明 |
|------|------|
| 拆解 | 大需求拆成小任务，人人能懂 |
| 沟通 | 说得清、听得懂、敢拍板 |
| 进度感 | 判断「按当前速度能否按时完成」 |
| 优先级 | 先做阻塞后做的，先做必须交付的 |
| 验收 | 看「做没做对」，不只「做没做完」 |
| 兜底 | 出问题不慌，带方案去解决或上报 |

## 四、怎么安排任务（实操模板）

```
【迭代：替换 Icon + 新增社区信息转换功能】

Day1  需求对齐：全员过需求，确认禁改范围
Day2  前端排期：王云 - Icon 替换（2天）
Day3  后端排期：张玉鑫 - 3 个接口（3天），先定接口文档
Day4  联调窗口：前后端联调（预留 1 天）
Day5  评审验收：图标核对 + 全流程回归 + 旧功能检查
Day6  缓冲 / 缺陷修复
Day7  交付总监终审
```

## 五、核心心法

- 项目经理不写代码，但要比谁都清楚「每块功能谁在做、做到哪、会不会拖」。
- 你的产出是「让别人按时做对」，而不是自己动手。
- 对外是第一责任人，对内是指挥 + 协调 + 裁判。
